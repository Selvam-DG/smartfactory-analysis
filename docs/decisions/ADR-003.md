# ADR-003: Why Random Forest over Deep Learning for Downtime Prediction

**Date:** 2026-05-01  
**Status:** Accepted

## Context

SmartFactory Reliability Analytics includes a machine learning pipeline that predicts machine downtime risk using historical sensor readings, production data, maintenance records, and breakdown history.

The data is privacy-safe and partly synthetic. The goal is to demonstrate a realistic ML workflow for predictive maintenance, including feature engineering, model training, prediction output storage, and dashboard visualization. The goal is not to build a safety-critical industrial prediction system.

## Decision

Use a Scikit-learn Random Forest classifier as the baseline downtime risk model instead of a deep learning model.

## Rationale

- Random Forest performs well on structured tabular data, which is the main data format in this project.
- It requires less data and tuning than deep learning, making it more appropriate for a synthetic/local demo dataset.
- It is easier to explain in interviews using feature importance, risk drivers, and business-friendly reasoning.
- It integrates cleanly with Scikit-learn pipelines, train/test splits, preprocessing, model persistence, and pytest-based testing.
- It is computationally lightweight and can train quickly on a normal laptop or Docker container.

## Alternatives considered

### Deep learning model

A neural network or LSTM-style model was considered because predictive maintenance can involve time-series patterns.

It was rejected for the current version because deep learning would require more data, more careful validation, longer training time, and more complex explainability. With synthetic data, a deep learning model could appear impressive but would not necessarily be more credible or useful.

### Logistic Regression

Logistic Regression was considered as a simple and explainable baseline.

It was rejected as the primary model because it may underfit non-linear relationships between sensor behavior, maintenance history, and downtime risk. It could still be used as a benchmark model in the future.

### Gradient Boosting

Gradient boosting models such as XGBoost, LightGBM, or HistGradientBoosting were considered.

They were not selected for the first version because Random Forest is simpler to explain, available directly in Scikit-learn, and sufficient for a portfolio-grade predictive maintenance baseline. Gradient boosting may be revisited later for improved performance.

## Consequences

### Positive consequences

- Faster model development and training.
- Good fit for structured industrial analytics data.
- Easier explanation of model behavior to recruiters and interviewers.
- Lower compute requirements than deep learning.
- Simple integration with the existing Python and Scikit-learn stack.

### Negative consequences

- Random Forest may not capture complex temporal dependencies as well as sequence models.
- Prediction quality is limited by the realism of the synthetic labels and generated data.
- Feature importance is useful but not as detailed as advanced explainability methods such as SHAP.
- Model performance may plateau compared with tuned gradient boosting models.

## Review date

Review this decision if real historical sensor and downtime data becomes available, if the dataset grows beyond 10 million labeled training rows, if time-series sequence modeling becomes a core requirement, or if Random Forest performance is not sufficient against benchmark models.
