# ADR-002: Why Streamlit over FastAPI + React for the Dashboard

**Date:** 2026-05-01  
**Status:** Accepted

## Context

SmartFactory Reliability Analytics needs a dashboard that can present OEE, downtime, production volume, reliability metrics, downtime Pareto analysis, anomaly flags, and downtime risk predictions.

The dashboard is primarily intended for local portfolio demonstration, recruiter review, and technical interviews. The goal is to show the data engineering and analytics workflow clearly rather than build a production-grade web application with separate frontend and backend services.

## Decision

Use Streamlit for the dashboard instead of building a separate FastAPI backend and React frontend.

## Rationale

- Streamlit enables faster development of interactive data dashboards using Python, which aligns with the project’s Python data engineering focus.
- The dashboard can directly use pandas, Plotly, and SQL query results without creating and maintaining a separate REST API layer.
- For a portfolio project, Streamlit reduces frontend complexity and allows more time to focus on ETL, SQL modeling, KPI logic, testing, and ML pipeline quality.
- Streamlit is easy for reviewers to run locally with a simple command or Docker Compose service.
- The project does not currently require complex frontend state management, authentication, multi-user workflows, or custom UI components that would justify React.

## Alternatives considered

### FastAPI + React

FastAPI and React were considered because they are a strong choice for production web applications with clear frontend/backend separation.

They were rejected for the current version because they would significantly increase project scope. A separate API, frontend build system, routing, state management, and deployment setup would add complexity without improving the main goal of demonstrating industrial reliability analytics.

### FastAPI + simple HTML templates

This option was considered as a lighter alternative to React.

It was rejected because Streamlit provides better built-in support for interactive filters, charts, tables, and quick data exploration with less custom code.

### Power BI or Tableau

BI tools were considered because they are common in enterprise reporting.

They were rejected because this project is intended to demonstrate Python development, open-source tooling, local reproducibility, and end-to-end engineering rather than dependency on a commercial BI platform.

## Consequences

### Positive consequences

- Faster dashboard development.
- Entire analytics application remains Python-centered.
- Easier local demo setup for interviews.
- Less frontend boilerplate and fewer moving parts.
- Good integration with pandas and Plotly.

### Negative consequences

- Streamlit is less flexible than React for complex custom UI design.
- Limited support for large multi-user production deployments.
- Authentication and role-based access control are not included by default.
- The dashboard may not represent a full enterprise web architecture.

## Review date

Review this decision if the dashboard needs authentication, role-based access, high concurrency, external API consumers, custom frontend workflows, or deployment as a production web application.
